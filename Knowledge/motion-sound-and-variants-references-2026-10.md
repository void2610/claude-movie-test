# 音の層と「案を並べて選ぶ」反復の参考事例 (2026-10-10 調査)

## 1. opus-sound-layer (@0xCodila, github.com/Bodila51/opus-sound-layer)

「Claude は自分の音を聞けないので、効果音が合成のビープ音になり、絵からずれる」ことへの対策。プロンプト (PROMPT.md) と 3 本のスクリプトから成る。

- **実録音だけを使う**: `sfx.py kit` が CC0 の録音 1,139 個 (Kenney の 7 パック + Freesound) を 19 種 (hit boom riser reverse transition whoosh swish glitch ui click key tick tap pop thump paper chime shimmer zap) に分けて取り込む。打撃・クリック・ウーシュの合成は禁止。足りなければ Openverse API で CC0 を探し、判定して追加する。出典は CREDITS.md に残す
- **音は見て選ぶ**: `sfx.py browse --type hit --like "metal heavy"` が候補を種類・タグ・長さ・明るさで並べ、波形とスペクトログラムの画像を出す。1 本の作品で音の系統を 1 つに揃える (例: ガラス + 空気、金属 + 低音)。同じ音の繰り返しは ±2% のピッチで揺らす
- **キューは絵の時刻から書き出す**: 手でフレーム番号を打たない。各キューに絵の出来事の種類を付ける: `cut` (画面全体の変化)・`move` (速さが最大のコマ)・`land` (動きが止まるコマ)・`appear` (要素が出る)。約 4 秒に 1 つだけ「ヒーロー」(ロゴ・見せ場) を置き、`hit+boom` を重ね、ライザーかリバースをそこに頂点を合わせ、直前 0.4 秒は音楽を止め (`stop_before`)、2 秒前からハイパスで盛り上げる (`build`)
- **ミックス**: 音の山をキューに合わせる。音量は「その音の帯域で、音楽 + 声に対して何 dB 浮くか」で事件ごとに解く (+3.5 dB、ヒーロー +5)。全効果音を 1 つの短い残響 (0.6 秒、-16 dB) に通して、出所の違う録音を同じ部屋に置く。-14 LUFS、トゥルーピーク -2 dBTP のリミッター (AAC 後に -1 dBTP を守るため)
- **QA は書き出し後の MP4 を測る** (`qa.py`、失敗で終了コード 1):
  - 絵との一致: 160×90 の灰色にした連続フレームの差分で動きの曲線を作り、`cut` は ±1 コマに大きな変化、`move` は ±3 コマに動きの山、`land` は ±2 コマで動きが止まる、を確かめる
  - 同期: 音の山がヒーローは 1 コマ、他は 2 コマ以内
  - 聞こえるか: 音の主な帯域 (エネルギーの 10% 以上を持つ帯域) で、音楽 + 声より 1.5 dB 以上浮く。ヒーローは最大の帯域で 3 dB 以上
  - 音楽が予定外に 12 LU 落ちない、0.5 秒以上の無音が無い、声の下で音楽が 8 LU 以上下がる、ラウドネス ±1 LU、トゥルーピーク ≤ -1 dBTP、エンコード後の音のずれ ≤ 1 ms
  - qa.png: 波形・スペクトログラム・絵の動きの曲線を縦に並べ、全キューに線を引く。ヒーローの位置で何が見えるかを言葉で書かせる
- **納品**: LISTEN.md に「人間が耳で確かめる 5 つの時刻」を書く。「音は良い」とは言わせず、測った結果だけを報告させる

## 2. fframes と「案を並べる」反復 (@iamashtonchew, @neogoose_btw)

- Remotion から fframes (Rust + SVG、Skia を Metal/Vulkan で描く、静的な部分はコンパイル時にハッシュして使い回し、libav を直接リンク) に替えて、作品の書き出しが 700 秒 → 21 秒未満。60fps・2 秒 (120 フレーム) のシーンで 20 倍速い
- 主張: **書き出しが速いと、1 つのシーンに案を何本も作って細部を詰められる。その積み重ねが「slop でない」動画になる**。遅い道具は間接的に凡庸さを生む
- 1 つのシーンの案を並べて見るウェブページを作らせる (@neogoose_btw の例: 「A jump, or a turn?」)。案ごとに動画・1 行の説明・出典を並べ、「全部を頭から再生」「全部止める」で同期して見比べる。1 案 1〜2 秒で書き出せるので成り立つ
- 音を先に決めてシーンを音に従わせる。事前にサブエージェントで参考例を調べさせ、「好きな点と嫌いな点の両方」を伝えて方向を決める
- fframes の CLI はエージェント用の確認手段を揃えている: `inspect` (0.25 秒ごとに、キャンバスで切れた文字・欠けたフォントや画像を報告)、`strip` (コンタクトシート)、`onion` (複数コマを重ねて動きの軌跡とイージングを 1 枚で見せる)、`snapshot` (承認済み PNG との差分)、`audio analyze` (シーンごとのラウドネス・トゥルーピーク・クリップ・無音)

## このエンジンとの比較 (2026-10-10 時点)

| 項目 | このエンジン | 参考事例 |
|---|---|---|
| 効果音 | `sfx` は合成 (whoosh / riser / impact / click)。実録音はドラムの Dirt-Samples だけ | 合成を禁止し、CC0 の実録音を種類別に揃える |
| キューと絵の一致 | `comp.cues` で映像と音を同じ時刻にそろえる。`review` は「目立つ音の立ち上がりが無いカット」を数える | キューに cut / move / land / appear を付け、書き出した絵の動きの曲線で ±1〜3 コマを検査 |
| 聞こえるか | 全体の LUFS をそろえるだけ | 音ごとに自分の帯域で音楽より何 dB 浮くかを解き、検査する |
| 書き出しの速さ | liminal_poster の 120 フレーム (1080×1080): 本番 9.5 秒、`--draft` 5.9 秒 (CPU の skia + プロセス並列) | fframes は 120 フレームで約 1 秒 |
| 案の比較 | `--set key=value` で版を分けて書き出せるが、並べて見る画面は無い | 案を並べて同期再生するページ |
| 動きの確認 | `sheet` / `still` / `review` のシート | `onion` で動きの軌跡とイージングを 1 枚に重ねる |
