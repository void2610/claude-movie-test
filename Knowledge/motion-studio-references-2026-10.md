# 参考事例の調査 (2026-10-09)

ユーザーから共有された X の投稿 5 件と motionpromptgallery の調査結果。

## rari「Motion Engineering: Build a Video Studio Around Opus 5.5」(x.com/0xwhrrari/status/2105643919119696297)

最も示唆が大きかった記事。要点:

- Opus 5.5 製の動画の多くは同じデモに見える: 中央の大きな文字、背景のグラデーション、全部フェードイン、最後にロゴ。差は秘密のプロンプトではなく、モデルの周りの仕組みにある
- スタジオは 5 層: DIRECTOR (何を伝えるか) / REFERENCE (どう見えるべきか) / TIMELINE (拍ごとに何が変わるか) / RENDERER / CRITIC (何がどこでなぜ失敗したか)。モデルが空いた決定を「無難な既定値」で埋めることが凡庸さの原因
- 演出意図ではなく制作文書を先に渡す: 一文の主張、尺、形式、実物の素材、守るもの・避けるもの、「製品画面や数値を捏造しない」
- 参照は検査できる形で渡し、パレット・書体・構図・ペース・動き・質感を書き出させる (コピーはしない)
- ストーリーボードは効果の羅列ではなく「各時点で視聴者が何を知っているか」。各ビートに入りの状態・出の状態・存在理由
- 動きは種類ごとにルールを決める: 小さな UI は速くほぼ行き過ぎない / パネルは制御された収まり / カメラはほぼ気づかれないほど滑らか / 見出しは強く入って読めるだけ止まる。全部をばねにすると何も精密に見えない
- 音は同じタイムラインに載せる。目を閉じて聴いて形がなければ音作りは未完成
- 書き出し前にコンタクトシートを見る。主要ビートごとに 1 枚 + 速いトランジション周辺の連続コマ。チェック: スマホサイズで読める / セーフエリア / 実物の素材 / 書体と色の一貫性 / 中途半端なトランジションのコマ / カットと音の一致 / 最初の 2 秒にフック / 最後のコマがポスターになる
- 批評は「最も大きな欠点 3 つ、それぞれに時刻・根拠・局所的な修正」を出させ、該当区間だけ直して再レンダリング
- 縦長版は横長版の切り抜きではなく別の構成 (文字を大きく、同時に出す要素を減らし、縦の階層を強く)
- 判断はチャットではなくファイルに残す: brief / style-guide / shotlist / assets / reviews / out
- 長い自走にはゲートを置く: 参照と素材の承認 → スタイルとショットリスト → 代表静止画 → ラフとコンタクトシート → 上位 3 欠点の修正 → 音・形式・納品物

## motionpromptgallery (github.com/mikenevermiss/motionpromptgallery、178 作品)

- タグの多い順: motion 99 / 3d 59 / canvas 58 / svg 31 / gsap 25 / explainer 24 / webgl 22 / threejs 18 / shader 17。3D とシェーダーの比率が高い
- 上位作品の特徴: 1080x1080 の正方形で「動く街頭ポスター」(パレットを 3〜4 色に厳密に固定、衝撃のコマでマゼンタと緑を 2〜4px ずらす印刷のずれ)、最初と最後のコマが一致するループ、分解して見せる 3D の解説、説明のたびに作風を変える構成、昔のコラージュ風の無限ズーム
- アスペクト比は 16:9 が中心だが、1:1 と 9:16 も多い

## このエンジンへの示唆 (採用)

1. 作品ごとの制作文書 (brief / style / shotlist) とひな形を作る `motion new`
2. ショットリストをエンジンのデータにして、タイミング・レビュー・音のキューの元にする
3. レビュー用シート: ショットごとのコマ + トランジション周辺の連続コマ + 波形とキュー + セーフエリア + スマホサイズでの可読性
4. 動きのルールを種類別のプリセットにする (micro / panel / camera / headline / playful)
5. 2.5D (遠近のある平面) を描けるようにする。3D の比率が高いため
6. 質感の語彙: 紙、ハーフトーン、印刷のずれ、紙が破れるトランジション、ループの検査
